# Curated subset for TRAINING only (not a full lockfile). MLIP-scoring/eval
# extras (mace-torch, e3nn) are in requirements-eval-optional.txt — they're not
# needed to launch training and have their own strict, easily-conflicting torch
# version requirements, so they're kept separate (same split steering/crystals/
# uses: requirements.txt vs. requirements_3mlip_optional.txt).
#
# torch is deliberately NOT pinned here. +cuXXX build tags (as seen in some
# reference environments) are PyTorch's own local version tags and are not
# resolvable from plain PyPI — pip fails outright on them without also pointing
# at https://download.pytorch.org/whl/<cuXXX>. Check for a working CUDA torch
# already on your machine first (common on GPU VM images):
#
#   python3 -c "import torch; print(torch.__version__, torch.cuda.is_available())"
#
# If that works, leave it alone and just install the rest of this file. If not,
# install torch yourself per https://pytorch.org/get-started/locally/, matching
# your actual CUDA version, before installing the rest of this file. Versions
# seen working in different reference environments for this project: 2.9.1
# (cu129) and 2.7.0 (cu128) — neither is a hard requirement.
#
# Everything below is a FLOOR, not an exact pin, and deliberately so: every
# exact pin originally in this file broke on the first real test machine
# (2026-11-05) — pymatgen 2026.5.4/pymatgen-core 2026.4.16 need Python >=3.11
# and failed outright on a 3.10 image; re-pinning huggingface_hub and ase to
# older exact versions then regressed newer, already-working installs of both
# (huggingface_hub 1.23.0 -> 1.14.0 broke a diffusers 0.40.0 install; ase
# 3.29.0 -> 3.28.0 was an unnecessary downgrade). If a package already
# installed satisfies the floor, leave it alone rather than force pip to
# match these numbers exactly. `pymatgen`/`pymatgen-core`'s floor reflects the
# newest version confirmed to still support Python 3.10 (2025.10.7) — don't
# let pip pull 2026.x on a 3.10 interpreter.
